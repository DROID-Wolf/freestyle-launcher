# Themes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add six switchable themes (Aurora, Window, Fireplace, Rainy café, Aquarium, Snowy cabin) to the launcher. The user picks a theme in a new Customize → Themes tab. Realistic scenes are made from stock video seen through room pictures. The dock and the preferences are untouched.

**Architecture:** The widgets we already have stay single shared elements. A pure registry (`themes.js`) describes each theme's options and resolves a *scene spec* (room picture, video slots, layout). A DOM renderer (`scene.js`) builds that scene in a new `#scene` layer behind the widgets. Per-theme CSS positions the widgets and masks the videos to each room's window panes.

**Tech Stack:** Vanilla ES modules, no build step. `node --test`. CSS masks (`-webkit-mask-image` with SVG). HTML5 `<video>`. GitHub Pages. Assets come from Pexels/Pixabay and from AI image generation through the Canva connector.

**Spec:** `docs/superpowers/specs/2026-10-18-themes-design.md`. Visual drafts are in `.superpowers/brainstorm/themes-1792316207/content/`.

## Global Constraints
- Chromium ~94 (Tizen 7): no `structuredClone`, no top-level `await`, no CSS `:has()`.
- Only `transform` and `opacity` may be animated. The design is 1920×1080; `.screen` is scaled by `fit()`.
- No npm dependencies and no bundler. Tests run with `npm test`.
- Each media file must be under 100 MB, and all media together about 100–150 MB. Do not use Git LFS (GitHub Pages doesn't serve LFS files).
- **Every download needs the user's explicit yes**, given per file with its name, source URL and size. Asset licences go in `app/media/CREDITS.md`.
- Prefs: `fl.prefs` gains `theme` (default `'aurora'`) and `themeOptions` (default `{}`). Nothing in this feature writes to `fl.dock` or to any other existing pref field.
- Media is served from the site-root `media/`, never from inside `v/<build>/`. `build-fallback` excludes `media/`.
- **Commits:** Claude does not commit. Each "Checkpoint" step means the user commits and pushes in GitHub Desktop with the given message.
- **Deviation from spec §4.1 (approved with this plan):** room pictures are opaque WebP files. The window, hearth or tank "cut-out" is a CSS mask on the video slot, not alpha in the image. This PC has no Pillow, ffmpeg or ImageMagick, and masks look the same on screen.
- The Live view uses the clip ids `city-rain`, `city-night`, `snowy-forest` and `beach`. Theme clips are `fire` and `aquarium`.

## Review Focus
1. **Upgrade from today's saved prefs** (no `theme` fields) must load as Aurora with default options and leave the dock and city untouched. Test in Task 3 (`loadPrefs` on today's prefs shape).
2. **A theme saved while offline or with media missing** shows Aurora, but the saved theme must not be overwritten. Test in Task 4 (the renderer's fallback never calls `onChange`), plus a browser check.
3. **A cleared window style (`null`) must survive** switching to another theme and back. Test in Task 2 (`cleanThemePrefs` keeps `null` for `allowNone`), plus Task 5's picker check.
4. **The Live view at the exact sunrise or sunset minute, and with no weather cache.** Test in Task 2 (`liveView` boundaries: `nowMin === setMin` counts as night, `nowMin === riseMin` counts as day; a `null` icon uses day or night only).
5. **The 15-minute weather refresh re-applies the same scene.** The video must not restart. Test in Task 2 (`sceneKey` is equal for equal specs), and the renderer skips the work when the key is unchanged (Task 4).

### Task 2: Theme registry and Live view (`app/js/themes.js`)

**Files:**
- Create: `app/js/themes.js`, `app/tests/themes.test.js`

**Interfaces:**
- Produces:

  - `THEMES`: an array of `{ id, name, thumb: 'media/thumbs/<id>.webp', options: Option[], scene(opts, ctx) }`, in this order: `aurora, window, fireplace, cafe, aquarium, cabin`.

  - `liveView(icon, nowMin, riseMin, setMin) -> clipId`.
  - `sceneKey(spec) -> string` (equal specs give equal keys).
  - `resolveScene(themeId, themeOptions, ctx) -> spec`, which uses the cleaned options.

### Task 4: Scene renderer and main.js wiring

**Files:**
- Create: `app/js/scene.js`, `app/css/themes/aurora.css`
- Modify: `app/index.html` (add `<div id="scene"></div>` as the first child of `.screen`, and a `<link>` for each theme CSS file), `app/css/styles.css` (move the aurora blob and theme-colour rules into `themes/aurora.css`), `app/js/main.js`

**Interfaces:**
- Consumes: `resolveScene`, `sceneKey`, `CLIPS` (Task 2), and `mediaUrl` (Task 1).
- Produces: `createSceneRenderer(screenEl, { mediaUrl: (p) => string, timeoutMs = 8000 }) -> { apply(themeId, spec), setPaused(paused: boolean) }`.
  - `apply` does nothing when `sceneKey(spec)` and `themeId` are unchanged.
  - Otherwise it preloads the room. It sets the `.screen` classes `theme-<id>` and `layout-<spec.layout>`, replacing the old `theme-*` and `layout-*` classes. It builds `#scene` with an optional `<img class="room">` and, per video, `<div class="slot slot-<slot>"><video muted loop playsinline autoplay preload="auto" poster=…>`.
  - If the room or the first video fails, or is not playing within `timeoutMs`, it adds the class `scene-fallback` to `.screen`. Aurora's background then shows through. The renderer has no access to prefs, so the saved theme is never changed.
  - `setPaused(true)` pauses every video (the poster stays visible).

- [ ] **Step 1: Wire `main.js`.** Add `currentCtx()`, which returns `{ icon, nowMin, riseMin, setMin }` from `cache` and `sun()`. Add `applyTheme()`, which calls `renderer.apply(prefs.theme, resolveScene(prefs.theme, prefs.themeOptions, currentCtx()))` and then `renderer.setPaused(prefs.reduceMotion)`. Call `applyTheme()` at startup, inside `applyPrefs()`, after each successful `refreshWeather`, and in `tick()` when the minute changes. Idempotency keeps that last call cheap.
- [ ] **Step 2: Browser check** with `python -m http.server -d app 8080`, using only `city-rain.mp4` from Task 1:

  - Calling `applyTheme()` twice keeps the same `<video>` element: compare the element references, and `currentTime` keeps increasing.
  - With Reduce motion on, the video is paused.
  - Aurora looks the same as before Task 4 (compare screenshots).

### Task 8: Theme layouts (CSS) and masks

**Files:**
- Create: `app/css/themes/{window,fireplace,cafe,aquarium,cabin}.css`
- Modify: `app/index.html` (the `<link>` tags, if Task 4 didn't add them all)

**Interfaces:**
- Consumes: the `.screen` classes `theme-<id>` and `layout-<layout>`, and `#scene .room` / `#scene .slot-<slot>` (Task 4).
- Produces: one CSS block per layout: `window-{desk,loft,train,attic,highrise,sunroom,porch,full}`, `fireplace`, `cafe`, `aquarium`, `cabin`. Each block does three things:
  1. **Masks the video slot to the room's panes.** The `.slot-<slot>` covers the full 1920×1080 frame, and `-webkit-mask-image` is an inline SVG data URL of white pane shapes. The pane coordinates are measured on that room's picture (open it at 1920×1080 in the browser and read the rectangles or ellipses).
  2. **Places the widgets** according to the approved drafts: the clock on the mantel, desk screen or chalkboard, and so on. Use `.screen.layout-x .clock { … }` and the same pattern for `.wx`, `.dock`, `.quote` and `.top`.
  3. **Ensures readability** with a text shadow or a soft panel wherever the clock and weather sit over a busy scene.
  - `window-full` makes the slot full-frame with no mask and adds today's left-side dark fade.
  - `cabin`: if Task 1 ruled "cabin window uses poster still", the renderer gets `stillSlots: ['view']` for the cabin. In that case `scene()` returns that slot with `still: true`, and the renderer shows its poster as an `<img>` instead of a `<video>`. Add a test for this in `themes.test.js`.
